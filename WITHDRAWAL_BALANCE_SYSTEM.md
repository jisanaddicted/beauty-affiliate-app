# Withdrawal Balance System Documentation

## Overview
This document explains how the withdrawal balance system works in the beauty affiliate platform.

## Balance Types

### 1. `pendingBalance`
- **Definition**: Commissions from orders that are "On Way" (not yet delivered)
- **Behavior**: 
  - Increases when new orders are created (via Google Sheets sync)
  - Moves to `withdrawableBalance` when orders are marked as "Delivered"
  - Temporarily holds withdrawal amounts when a payout is requested
  - Cleared when withdrawal is approved or rejected

### 2. `withdrawableBalance`
- **Definition**: Funds available for the affiliate to withdraw
- **Behavior**:
  - Increases when `pendingBalance` orders are delivered
  - Decreases when a withdrawal is requested (moved to `pendingBalance`)
  - Increases when a withdrawal is rejected (returned from `pendingBalance`)
  - **Never affected by approval** (already deducted when requested)

### 3. `totalEarned`
- **Definition**: Lifetime total earnings (all delivered commissions)
- **Behavior**:
  - Increases when new orders are delivered
  - **NEVER DECREASES** - represents historical earnings
  - Used to track total value generated by affiliate

## Withdrawal Flow

### Step 1: Withdrawal Request
**File**: `backend/routes/payouts.js` (lines 11-62)

```javascript
// When affiliate requests withdrawal:
affiliate.balance.withdrawableBalance -= amount;  // Deduct from available
affiliate.balance.pendingBalance += amount;       // Hold in pending
```

**Result**: 
- Affiliate sees reduced `withdrawableBalance` immediately
- Funds are held in `pendingBalance` awaiting admin approval

### Step 2: Admin Approval
**File**: `backend/routes/adminRoutes.js` (lines 70-102)

```javascript
// When admin approves withdrawal:
affiliate.balance.pendingBalance -= amount;  // Clear from pending
// totalEarned stays the same (lifetime earnings)
// withdrawableBalance stays the same (already deducted)
```

**Result**:
- Funds permanently removed from affiliate account
- `pendingBalance` cleared
- Balance never returns to dashboard ✓

### Step 3: Admin Rejection
**File**: `backend/routes/adminRoutes.js` (lines 105-137)

```javascript
// When admin rejects withdrawal:
affiliate.balance.withdrawableBalance += amount;  // Return to available
affiliate.balance.pendingBalance -= amount;       // Clear from pending
```

**Result**:
- Funds returned to `withdrawableBalance`
- Affiliate can withdraw again ✓

## Frontend Integration

### Affiliate Dashboard (App.jsx)
- Displays three balance cards: Pending, Withdrawable, Total Earned
- Uses `skipBalanceSync` flag to prevent Google Sheets sync from overwriting withdrawal balances
- Calls `onBalanceUpdate` callback when withdrawal is submitted

### Payouts Tab (PayoutsTab.jsx)
- Shows withdrawal form with available balance
- Submits withdrawal request to backend
- Updates parent component balance via `onBalanceUpdate` prop
- Refreshes withdrawal history after submission

### Admin Panel (AdminPanel.jsx)
- Shows pending withdrawal requests
- Approve/Reject buttons update withdrawal status
- Backend automatically adjusts balances
- Removes processed withdrawals from pending list

## Balance Calculation Logic

### Google Sheets Sync (affiliateController.js)
```javascript
// When syncing with Google Sheets:
pendingBalance = sum of "On Way" order commissions
withdrawableBalance = sum of "Delivered" commissions - total approved withdrawals
totalEarned = sum of "Delivered" commissions (lifetime)
```

**Important**: The sync endpoint calculates `withdrawableBalance` by subtracting only **approved** withdrawals from delivered commissions. This ensures rejected withdrawals don't affect the balance.

## Key Rules

1. ✅ **Withdrawable balance decreases immediately** when withdrawal is requested
2. ✅ **Balance never returns** if withdrawal is approved
3. ✅ **Balance returns** if withdrawal is rejected
4. ✅ **Total earned never decreases** (lifetime tracker)
5. ✅ **Pending balance** acts as holding area during approval process
6. ✅ **Frontend prevents sync overwrite** after withdrawal using `skipBalanceSync` flag

## Database Schema

### Affiliate Model
```javascript
balance: {
  pendingBalance: Number,      // Default: 0
  withdrawableBalance: Number, // Default: 0
  totalEarned: Number          // Default: 0
}
```

### Withdrawal Model
```javascript
{
  affiliateId: ObjectId,       // Reference to Affiliate
  amount: Number,              // Withdrawal amount
  method: String,              // bKash, Nagad, Rocket, Upay
  accountType: String,         // Personal or Agent
  accountNumber: String,       // Mobile number
  status: String,              // Pending, Approved, Rejected
  createdAt: Date,             // Request timestamp
  approvedAt: Date,            // Approval timestamp (if approved)
  rejectedAt: Date             // Rejection timestamp (if rejected)
}
```

## API Endpoints

### POST /api/payouts/withdraw
- **Access**: Affiliate (authenticated)
- **Purpose**: Request withdrawal
- **Effect**: Deducts from withdrawableBalance, adds to pendingBalance

### PUT /api/admin/withdrawals/:id/approve
- **Access**: Admin (authenticated)
- **Purpose**: Approve withdrawal request
- **Effect**: Clears pendingBalance, funds permanently removed

### PUT /api/admin/withdrawals/:id/reject
- **Access**: Admin (authenticated)
- **Purpose**: Reject withdrawal request
- **Effect**: Returns funds to withdrawableBalance, clears pendingBalance

### GET /api/payouts/history
- **Access**: Affiliate (authenticated)
- **Purpose**: Get withdrawal history
- **Returns**: Array of withdrawal records

### GET /api/admin/withdrawals
- **Access**: Admin (authenticated)
- **Purpose**: Get withdrawal requests (filtered by status)
- **Returns**: Array of withdrawal records with affiliate info

## Recent Changes

### Fixed: Balance Deduction on Approval
**Date**: 2026-07-03
**Issue**: When admin approved withdrawal, `totalEarned` was incorrectly decreasing
**Fix**: Removed the line that decreased `totalEarned` on approval
**Reason**: `totalEarned` represents lifetime earnings and should never decrease. The funds were already deducted from `withdrawableBalance` when the withdrawal was requested.

**Before**:
```javascript
affiliate.balance.pendingBalance -= withdrawal.amount;
affiliate.balance.totalEarned -= withdrawal.amount;  // ❌ WRONG
```

**After**:
```javascript
affiliate.balance.pendingBalance -= withdrawal.amount;
// totalEarned stays the same ✓
// withdrawableBalance already reduced when requested ✓
